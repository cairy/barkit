# 识别设计（recognize · 已实现 as-built）

> **一句话**：菜单栏触发的一条 OCR+条码二合一识别流水线——图片来自剪贴板或文件，支持图内框选多区域，并行跑文字与条码识别，结果可逐段/逐条复制。
>
> **状态**：✅ 已实现（2026-08 落地，P1 recognize）。本文为**已实现设计**（as-built），描述代码当前形态；契约接口以 `组件契约规范.md` 为唯一真源。

## 流程

```
热键/菜单触发 → 打开识别窗口（左=图片区，右=结果区）
  ├─ 剪贴板有图片 → 图片区直接载入预览（系统 ⌃⌘⇧4 截屏到剪贴板，与此天然衔接）
  └─ 剪贴板无图片 → 图片区即为拾取态（占位提示，点击选文件 / 拖拽图片文件）
  └─ 图片区随时可换图（再次拖入/选择文件替换）
  └─ [框选] → 图片预览区内直接拖选多个矩形（rubber-band，Esc 清空）
↓
[识别] → 同一张图并行跑：
  ├─ recognize_image_text(image, regions=选区)   # mac-ocr-text
  └─ read_barcodes_from_image(image, regions=选区) # mac-barcode-read
↓
结果区：文字段（整块一键复制 + 逐段复制）｜ 条码列表（逐条复制）
```

## 要点

- **图片区二合一**：预览与拾取是同一窗口的两种初始状态，有图即预览、无图即拾取，不拆两个窗口。
- 图片来源只有两种：剪贴板、选择/拖入文件。**不做内置截屏**——用户可用系统截图（⌃⌘⇧4 存剪贴板）衔接，少一个权限依赖。
- **框选作用于图片而非屏幕**（评审定案）：对拖入/载入的图片文件，屏幕级框选与图片内容无对应关系，选区无法落地；故框选在图片预览区内完成（QGraphicsView），选区按预览缩放比例自动换算为图片像素归一化坐标，Retina 下天然正确。放弃全屏覆盖层方案。
- 两个库的 `regions` 均为归一化 top-left 坐标，与上述换算天然对齐。
- 识别器各自可在配置中关闭（纯 OCR 场景跳过条码检测）。
- 框选是纯 UI 工作，无额外权限。

## 配置段（示意）

```yaml
plugins:
  recognize:
    enabled: true
    ocr:
      enabled: true
      languages: [zh-Hans, en-US]
      recognition_level: accurate   # accurate | fast
    barcode:
      enabled: true
      # barcode_types: [qrcode, code128]  # 不填 = 全类型
```

## 实现约束（来自 `../README.md` 调度与线程模型，原 方案文档 §3.4）

- OCR/条码模块（pyobjc-Vision / PIL）**首次识别触发时才在 worker 线程懒加载**，启动不加载；识别完立即释放原图，只留结果文本——常驻内存目标 ≤150MB（见 `../README.md` 非功能需求）。
- 识别在 `QThreadPool` worker 线程并行执行（两个 `QRunnable`），不卡 UI。
