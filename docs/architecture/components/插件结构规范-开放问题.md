## 13. 开放问题决议

### 13.1 已定稿

1. **`Guard` → `AutomationCapability`**（§5.2）：改名保留，但**降级为低优先独立原子步**，与其它阶段 0 动作不耦合；`capabilities/guard.py` 的**归属不变**（§5.1 有 `capabilities/__init__.py:1-22` 明文依据）。
2. **`plugin.py` 行数上限**：**不设硬门禁**。硬线会逼作者用「一行多语句」规避；改为**软指标**（评审时看，>250 有效行须说明理由）+ **硬门禁 `test_plugin_py_has_no_pyside6`**（它才是「UI 不写在 `plugin.py`」的可判定切分线）。
3. **`plugin_support` vs 补基类**：职责二分（§6.1），已落地为 §6.2 的「归属」列。（`plugin_support` 2026-09-30 随零调用方删除；二分判据本身仍有效。）
4. **`_snapshot` 提取**：**不做公共算式提取**（§6.4），仅列为可选。
5. **`resources/` 与包内 `.md`**：原地不动（§3.2、§3.3、§3.4）。
6. **`SettingsPageSpec.schema`：保留字段、不接线**（§7.1）。**这更正了第 2 稿的「倾向 (a) 实现自动渲染器」**——依据是 §7.1 事实 3 + 4：6 个存量设置页全部走 `build` 且**没有一个是配置表单**（全是动作入口 + 说明），渲染器今天零受益者。结论随证据变，不是摇摆：把「未来可能需要」当成立即动工的理由，正是本规范要避免的无谓改动。配套加 **fail-fast**（收集期校验，把崩溃前移为加载期拒绝）。
7. **改名范围：模块名与测试文件名一并改**（§5.2 表）。同一原子步、同一文件集（模块文件本身是唯一增量），分两次做只会留下第二次无意义 diff；且 `guard` 的误导性在模块路径上同样成立。合计 **6 代码文件 + 2 文档**。
8. **helper 客户端的归属与命名定案：`core/helper_client.py`**（§8.1）。依据：`core/` 已有 `installer.py` / `rootbin_reconcile.py` / `helper_tasks.py` 三个同域物，共同构成「app 侧对 root helper 的客户端 / 对账 / 声明注入」；`capabilities/` 是能力 mixin 语义，`capabilities/helper/` 是系统域源码包（禁区）。同时锁定两个必改切分点（源码路径推导深度、`uninstall()` 内嵌 route 清理）。
 （**落点已改，别按这条的原名找**：2026-09-14 实测「`core` 禁 import `capabilities`」的分层门禁 ⇒ 改放 `capabilities/helper_client.py`，理由与冲突证据见 §8.1 的 ⟪改定案⟫ 表。两个切分点也已全部落地：切分点 1 = 2026-09-14；**切分点 2 = 2026-09-17**（`uninstall()` 内嵌路由清理已删，期望态撤销改由插件 `teardown()` ＋ 框架延迟收尾承担），见 §8.1 末与《重构完成台账-近期骨架》§A23。）
9. **`hosts_guard` 的 `store` / `resolve` 是否上提：关闭**。实测跨插件 import 全仓仅 2 处且都指 `route_guard.daemon`（§8.1），`hosts_guard.store` / `resolve` 零外部引用。无复用价值即不上提——「将来也许有人用」不构成上提理由。

### 13.2 挂账项（有明确启动条件，不再阻塞定稿）

1. **`schema` 自动渲染器接线**（§7.1 决议 3）。启动条件：出现第一个「纯配置表单」型插件，或存量页面中有 ≥1 个被判定为「本质就是若干配置项」。口径已备好（渲染器位置、取值/写回/校验路径、`LIST` 字段策略）。
 （**2026-09-14 复核**：`notify_guard` 的设置页重建为**规则编辑器**后仍是**自绘**（集合型），**不构成启动条件**。）
2. **`_snapshot` 尾部装配的轻量工具**（§6.4）：`snapshot(level, summary, *, detail, updated_at, rows)`，每处约省 1–2 行。可选、收益待证，不占任何阶段。**（2026-09-30 关闭：载体 `plugin_support` 已随零调用方删除。）**

### 13.3 已关闭议题（勿重开）

> **与本表并列的还有一份「勿重开」台账：《组件契约决议》§5。两者**不合并**，因为管辖范围不同**——
> 本表只管**包内组织**（文件放哪、能力怎么选），《决议》§5 管**字段 / 声明点 / 契约语义**。
> 关掉一个议题前，先确认它属于哪一栏；**两边都查一遍**再判。反例：`Guard` 改名属本表（模块归属），
> 而「计算属性挂 Spec」属《决议》§5（声明语义）——放错表会让另一方以为从未关闭。

| 议题 | 结论 | 依据 |
|---|---|---|
| `capabilities/guard.py` 是否挪位置 | **不挪** | `capabilities/__init__.py:1-22` 明文定义该包为能力 mixin 层 |
| `plugin.py` 行数硬门禁 | **不设** | 会被「一行多语句」规避；可判定切分线是「无 PySide6 import」 |
| 包内 `.md` 迁 `docs/` | **不迁** | wheel 实测 `.md` 占 9.6% vs hev 占 60.6%；`ipad_tunnel/design.md:4-5` 既存决议 |
| `resources/` 迁 `docs/` | **禁区** | `core/rootbin_reconcile.py:37,68,98`；挪走即断 A 类部署（§3.3） |
| `hosts_guard` store/resolve 上提 | **不提取** | 零跨插件引用（§13.1.9） |
