# 组件文档集

已定稿的设计提案。组件是 BarKit 唯一的一等公民扩展点，本集是其权威资料。

## 单一真源规则（铁律）

- **契约只在一处定义**：字段语义、声明点、基数以 `组件契约规范.md` 为准。
  开发指南、插件结构规范、设计提案一律**引用不重述**；复述即第二真源，会漂移。
- **代码为准**：规范描述的是「目标契约」；代码与规范冲突时改代码，不以现状覆盖规范意图。
- **配置默认值的真源是插件的 `config_schema()`**（§9.5）：出厂文件 `config.default.yaml` 只留
  框架级键 ＋ `plugins.<id>.enabled`，业务键写第二份就是第二真源（门禁
  `test_config_defaults_single_source`）。
- **变更同步**：改契约规范后，开发指南 / 插件结构规范 / 设计提案中涉及的引用须同步核对。

## 同步纪律

改以下任一份，必须同时核对其余几份是否仍一致（避免第二真源）：

1. `组件契约规范.md` — 字段 / 声明点变更
2. `插件结构规范.md` — 包结构变更
3. `组件开发指南.md` — 范例 / 字段引用变更
4. `组件契约决议.md` — 新决策追加
5. 两份设计提案 — 引用契约字段变更

> 来源：原「 §G 四件套同步纪律」。

## 版本说明

文件名已去除 `-v1/-v2/-v3` 后缀（本次文档重构 2026-09-15 决策）。去除的是**文件名版本号**，
不是版本概念本身——BarKit 的版本演进仍由代码中的多套闸门表达：

- 契约演变看 `api_version`（`SUPPORTED_API_VERSION`）；
- 配置结构看 `schema_version`；
- Spec 字段看 `SPEC_VERSION`；
- helper 协议看 `HELPER_VERSION`。

文件名不带版本号，是因为这些文档描述的是「当前目标契约」，演进由代码闸门追踪，不在文件名里叠版本。
