## 1. 为什么要收字段定义权

同一批字段此前有 **3 个副本**，已经开始分叉：

| 副本 | 位置 | 问题 |
|---|---|---|
| Spec 源码 | `src/barkit/contribution/specs.py` | **真源**，但只有字段名，没有语义 |
| 设计意图 | `../UI交互分层规范.md` §4.2 / §8.2 | **内嵌 dataclass 源码块**，与代码双写、必然漂移 |
| 上游方案 | `../主框架架构.md` §5 | 同上 |

已经发生的分叉：UI 规范 §4.2 的 `StateSpec` 示例带 `key` 与 `priority`，§4.3 规定「level 相同时取 `priority` 最大者」——实测全仓 **5 条 `StateSpec` 的 `key` 全为 `"main"`**（4 个真实组件 + 模板），`priority` **只有 1 处显式填写**。即这条「平级取 priority」规则**今天零实例**，却写在两份文档里当既有契约。

**结论**：字段定义权收归「契约规范 + `specs.py`」两处，其余文档只写引用。
