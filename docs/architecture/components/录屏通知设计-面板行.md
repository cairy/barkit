### 6.4.1 为什么必须自绘（结论不变）

契约 §2.8 的判据是"出现『第 N 项的第 M 个字段』这种两层索引就够格"。本组件的规则就是两层 —— **并且今天它根本没有编辑器**：`config_schema()` 把 `rules` 声明成 `FieldType.LIST`（`plugin.py:248`），而 **`FieldType.LIST` 全仓没有渲染器**（`core/schema.py:28-39` 定义了类型，没有任何 UI 代码消费 `FormSchema.fields`）。**结论：今天用户只能改 YAML。** 这就是你说"需要考虑可视化配置"的根因。

### 6.4.6 「启动时自动拉起 OpenDisplay」开关（2026-09-18）

本页第二枚开关（紧贴自动化总闸下面一行，同款 `Card` 行）：打开 ⇒ BarKit **启动的首拍**把
OpenDisplay 拉起来；不打开 ⇒ 什么都不做。**缺省是关**（`config_schema` 里 `default=False`
—— 「用户没设过」就是「不自动拉起」，这是判据本体、不是兜底值）。

| 装置态 | 做不做 | 为什么 |
|---|---|---|
| 开关关着 | **连 `app_state()` 都不探** | 默认路径不碰 AppKit；也保证无图形环境 / 既有用例零额外调用 |
| `idle`（装了没跑） | 拉起，且**只拉一次** | 这正是本开关要的那件事；tick 每 3s 一轮，没有闸会拉成循环 |
| `running`（已在跑） | **不动它** | `open -a` 对运行中的 App 走 `applicationShouldHandleReopen` ⇒ **弹窗体**；而「弹出窗体」是**整行点击**那个动作的意思（§6.5-A），不是本开关的意思 |
| `absent`（没装） | 不试 | 只会换来一次注定失败的 `open` 与一行 warning，而面板早写着「未安装 OpenDisplay」 |

- 落点：`plugin.py::_launch_on_startup_once()`（在 `tick()` 首行调）；读写在
  `open_on_startup` ＋ `set_open_on_startup()` ＋ `config_schema()` 的 `open_on_startup`；
  界面在 `settings.py`（`_launch_sw` / `_on_toggle_launch`）。
- **为什么在 `tick()` 而不在 `start()`**：调度器注册即点火（`Scheduler.add_plugin` 末尾的
  `_on_beat`），两者同一时刻到达；但 tick 跑在 worker 线程，而 `open -a` 是一次 fork/exec
  —— 放 `start()` 会挡在宿主启动路径上。
- **它是启动行为，不是状态**：改完**下次启动**才生效（写盘不动「已处理」闸），故成功不另给
  提示语；写盘失败才在列表页行内报错，并**把开关拨回原位**（界面不许显示一个没落盘的值）。
- 用例：`tests/test_notify_guard.py` 的 2.9 节（10 条：缺省为关 / 关着不探装置态 / 只拉一次 /
  已在跑不动 / 没装不试 / 读写往返 / 写失败返回 False 且读数不变 / 设置页开关往返 /
  开关初值取配置 / 写失败回滚控件）。
