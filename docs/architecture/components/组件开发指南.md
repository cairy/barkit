# 组件开发指南（Plugin / Component Developer Guide）

本指南面向**在 BarKit 之上开发组件（插件）的开发者**。组件是 BarKit 唯一的一等公民扩展点：你新增一个组件，无需改动任何注册/调度代码，框架会自动发现、加载、调度、并把它接入状态面板（以及通过全局热键暴露交互）。

> 本文所有 API 锚定 **v3 目标贡献契约**（`api_version = 3` ＋ 声明点方法声明式 Spec）；**代码落地进度见 **。**字段定义的唯一真源已收归 `组件契约规范.md`**；本指南讲**怎么用**，不再重复字段表。
>
> ⚠️ **阅读须知：声明入口已是目标形态（D20，2026-09-16 落地）。**
> 插件按声明点覆写具名方法——`component()` / `state_specs()` / `row_specs()` / `detail_entry()` / `settings_page()` / `actions()` / `hotkeys()`（方法名与基数以契约 §1.3 表为唯一真源）；Spec 的 `plugin_id` 由框架注入，组件不写。单一 `contributions() -> list` 入口已删除。
> 分篇里的示例已全部改成当前写法（◷ 2026-10-03 逐处核过）；写新代码以契约 §1.5 的完整例子为准。
>
> ⚠️ **配置读写都只有一个写法**（◷ 2026-10-03 落地）：读 `self.cfg.value("某键")`、
> 写 `self.cfg.set("某键", 值)` / `cfg.update({…})`。默认值与取值域一律回读你自己的
> `config_schema()`，调用点不再写 `.get(key, 兜底)`（那是第二份默认值，漂移时不报错）；
> 写侧**等于声明默认值即删键**（用户 YAML 是差异层，留同值键会把那个值钉死）。
> 见 §3.3「配置访问」与 §4.3「写用户配置」。
