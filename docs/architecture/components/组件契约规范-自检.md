## 4.1 提交前自检

- [ ] `id` 与目录名一致；`config.default.yaml` 里只加了 `plugins.<id>.enabled`，业务默认值在 `config_schema()` 里
- [ ] `version` / `api_version = 3` 已填
- [ ] 轮询型组件设了 `run_mode = RUN_PERIODIC`；会写系统的组件设了 `failure_policy = FAIL_BREAK`
- [ ] `tick()` 不碰界面、失败要 `raise`、返回 `StateReport`
- [ ] 每个 `StateSpec` 的 `states` 枚举了**全部**可能取值，且每个取值都写了 `level` 与 `text`
- [ ] 需要提醒到托盘的取值标了 `alerts=True`（`WARN` / `ERR` 默认已标）
- [ ] 每台状态机的 `initial` 指向一个真实存在的取值 id
- [ ] 报告里出现的取值名都在声明表里
- [ ] 需要操作引导的文案写进了详情页或行内按钮，没有塞进 `summary`
- [ ] 行声明里没有 `icon` / `title`——图标取 `ComponentSpec.icon`，名字取 `Plugin.name`
- [ ] 同一声明点内多条贡献时 `key` 唯一（跨声明点可同名）
- [ ] 只覆写了自己需要的声明方法，`plugin_id` 一个字都没写（框架注入）
- [ ] `RUN_PERIODIC` 的组件填了 `suggested_poll`，且**没有**在 `config_schema()` 里声明 `poll` 字段（用户侧的「运行间隔」控件由框架自动生成，D21）
- [ ] 动态数值都在报告里；声明里只有静态数据与**纯读取回调**（见 3.1）
- [ ] 取值回调（`get_checked` / `get_items` / `get_state` / `subtitle` …）无副作用、不依赖调用次数
- [ ] 取值集合来自用户数据时，`states` 里有一个兜底取值，且 `initial` 指向它
- [ ] 只有一台状态机就是一行；声明多行时 `reason` 说明了为什么面板必须同时看到它们
- [ ] 多台状态机需要一句话合并时用了 `StatusRowSpec.subtitle`；只有一台机时没写它
- [ ] `StatusRowSpec.on_click` 只做**就地一件事或唤起外部应用**；要打开**框架内**界面走 `detail_entry()`（见 2.4）
- [ ] 集合型配置（两层索引）自绘 `build` 并在 `reason` 里自述；入口按**使用频次**选（高频 → `detail_entry()`，配一次就不再动 → `settings_page()`）；`presentation` 按内容宽度选
- [ ] 唤起**外部应用**走了动作（`on_click` / `ActionSpec` / `ButtonSpec`），没有塞进 `detail_entry()`（它只承载框架内界面）
- [ ] 声明了 `StatusRowSpec.on_click` 时，已接受"框架合成的详情入口失效"（见 2.4）
- [ ] 组件的**运行前提**（依赖没装 / 能力缺失）有显式取值与文案，没有静默空转（见 2.2）
- [ ] 给出的**主图标**（`StateSpec.icon`）与其取值图标在菜单栏尺寸下可辨认（见 2.5）
- [ ] 需要权限的组件在 `required_permissions` 声明，并在使用前引导
- [ ] 写了断言「该组件能被发现」的测试

## 4.2 字段总表

| 你想做的事 | 写在哪 |
|---|---|
| 组件叫什么、叫什么 ID | `Plugin.name` / `Plugin.id`（类属性） |
| 标明组件版本 | `Plugin.version` |
| 决定周期轮询还是按需触发 | `Plugin.run_mode` |
| 建议多久轮询一次 | `Plugin.suggested_poll`（用户可覆盖：设置窗里**你这个组件页页尾**那个**运行间隔**下拉由框架自动生成，你不声明字段） |
| 组件自己的后台节律（如「多久重新解析一次」） | 另起一个配置键（如 `resolve_poll` / `helper_poll`）——**别复用 `poll`**：那一个是框架轮询 `tick()` 的间隔（见附录 A「一个配置键只服务一个消费者」） |
| 决定失败时熔断还是只记日志 | `Plugin.failure_policy` |
| 身份图标 | `component()` → `ComponentSpec.icon` |
| 声明一台状态机、枚举它的取值 | `state_specs()` → `StateSpec` + `StateOption` |
| 某个取值有多严重 / 什么图标 / 默认文案 | `StateOption.level` / `.icon` / `.text` |
| 这一格要不要提醒到托盘 | `StateOption.alerts` |
| 组件列表出现一行 | **不必声明**（恒有一行）；`row_specs()` → `StatusRowSpec` 只决定这一行长什么样 |
| 行右边的开关 / 菜单 / 按钮 | `StatusRowSpec.controls`（0–2 个） |
| 行的模式徽标 | `StatusRowSpec.mode` = `ModeBadgeSpec`（文案由你定，见 2.5） |
| 底部出现一个按钮 | `actions()` → `ActionSpec` |
| 全局热键 | `hotkeys()` → `HotkeySpec` |
| 设置页 | `settings_page()` → `SettingsPageSpec`（见 2.8） |
| 详情页入口 | `detail_entry()` → `DetailEntrySpec`（见 2.8） |
| 整行点击做什么 | `StatusRowSpec.on_click`（**优先**）：就地一件事 / 唤起外部应用；要打开框架内界面才用 `detail_entry()`（见 2.4） |
| 组件前提不满足时怎么表达 | 一个**显式取值**（如 `absent`）+ `text`，并让它进副标题（见 2.2） |
| 某一次报告想改文案 | `StateReport.summary`（**覆盖**取值声明的默认 `text`，留空即用默认）——注意**级别与图标不能在运行期改**：它们是取值的属性，要变就多声明一个取值（见 2.2） |
| 让某台状态机可被用户选作**菜单栏主图标** | 给它一枚**主图标** `StateSpec.icon`（有图标即取得资格，没有额外的开关）；用户侧在设置窗「通用」页改 `tray.base_source` = 状态机身份 `{组件 id}.{状态机 key}`（见 2.5） |
| 集合型配置（可增删的列表） | `build` 自绘；入口按使用频次选（`detail_entry()` / `settings_page()`，见 2.8） |
| 我现在处于哪个取值 | `StateReport.state`（`tick()` 返回） |
| 行的副标题 | 默认不用写（回退代表态 `summary`）；要多台状态机的信息就声明 `StatusRowSpec.subtitle` |
