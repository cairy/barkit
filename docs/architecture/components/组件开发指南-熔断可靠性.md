## 7. 熔断与可靠性（scheduler）

`scheduler` 对 daemon 组件内置可靠性机制（`core/scheduler.py`）：

- **每组件独立线程池**（maxThreadCount=1）：一个组件 `tick` 卡死不饿死其他组件。
- **tick watchdog**：单个 `tick` 超过 `TICK_TIMEOUT`（60s）按失败处理，迟到结果作废。所以 `tick` 必须快、可超时，长耗时要自己加子超时。
- **心跳驱动 tick**：所有组件的 tick 由单一心跳驱动（相位错开，见 `core/scheduler.py`）；每轮结果落到 `scheduler.status(id)` 的 `broken` / `fail_count` / `running` / `dirty`。**「守卫失联」不由 tick 是否跑通决定** —— 面板按**状态 topic 多久没收到事件**判（阈值取组件 `stale_after`）。所以别指望 `status()` 里有「上次成功时刻」，也不要往 scheduler 里加这类字段：那量没人读。
- **熔断按 `failure_policy` 分化**（这是该字段存在的唯一原因）：
  - `FAIL_BREAK`（有写入/执行动作，如 notify_guard / hosts_guard）：连续失败达 `FAIL_THRESHOLD`（5 次）自动停用（熔断），面板顶部出红色故障条 + 「重试」；并 `RETRY_DELAY`（30s）后自动重试。熔断期间不再轮询。
  - `FAIL_LOG`（只读状态刷新 UI，如 route_guard / ipad_tunnel 面板侧）：失败**只记日志，不熔断**——因为只读不应阻断。
- 你的 `tick` 在写入失败时应**抛异常**（`raise`），scheduler 才能计数；吞掉异常等于"成功"，会掩盖故障。

## 8. UI 贡献实践

`StatusRowSpec.custom` 工厂返回的控件应复用 `shell/ui_kit` 的现成元件，保持与全局一致的视觉语言：

| 元件 | 用途 |
|------|------|
| `StatusRow(icon_text, name, controls=(), badge=None, on_click=None, clickable=False, extra_refresh=None, parent=None)` | **面板状态行的标准容器**：图标 + 名称 + 右侧控件 **0–2 个**（元组，顺序即从左到右）+ 名称后徽章。构造器**没有 `sub` / `title` / `icon` 参数**——副文本须经 `row.set_sub(text, tooltip=...)` 设置。**只在 `custom` 逃生舱里用**（`autotype` 是当前唯一消费方）；声明式组件走 `StatusRowSpec.controls`，由框架渲染 |
| `Badge(auto=..., parent=...)` | 状态徽章（自动/手动等），`set_mode(auto)` 切换，`clicked` 信号 |
| `Switch(parent)` | 开关，`setChecked`/`isChecked`，`clicked` 信号 |
| `_ChevronButton` / `Card` / `ProfileSelector` / `ElideLabel` / `HStatChip` / `Divider` / `LogoWidget` | 其它可复用件（详见 `ui_kit`） |

设计语言约束（与 `../UI交互分层规范.md` 一致）：

- **pill-ghost 风格**：透明底 + 1px 描边，hover 转 `surface2` 灰底 / `accent` 描边。
- **圆角半径随尺寸缩放**：大元素（图标盒/按钮）用 ~8px；小徽标（~18px 高）用 ~5px。**不要全项目统一一个半径值**——在 32px 元素上 8px 是圆角矩形，在 18px 徽标上 8px 就接近药丸了。
- **主题色从 `ui.styles.TOKENS` 取，不要用硬编码色值**：

  ```python
  from barkit.shell import styles
  t = styles.TOKENS[styles.current_system_theme()]
  bg = t["accent_soft"] # 注意：key 无下划线！是 accent_soft / surface3 / text3
  ```

  > ⚠️ `styles.TOKENS` 的 key **没有下划线**（`surface3`、`text3`、`accent_soft`…）。写成 `surface_3` / `text_3` 会在运行期 `KeyError` 崩溃（`_theme_tokens()` 在 paint/refresh 时才取值）。
- **圆角背景必须自绘**，勿依赖 QSS `border-radius`：macOS 上对普通 widget，QSS 的 `border-radius`/`background` 不裁剪背景，只会得到直角矩形。`Badge`/`Card` 都用 `QPainterPath.addRoundedRect` 自绘。
- 面板行主题刷新由 `StatusRow` 统一管理；组件自绘控件需实现 `refresh_theme(*_args)` 并在 `extra_refresh` 里挂上，保证 light/dark 切换时重绘。

## 9. 权限与 PyObjC

- 需要系统权限的组件，在 `required_permissions` 声明，并在实际使用前引导：

  ```python
  from barkit.core.permissions import accessibility_trusted, ensure_accessibility
  if not accessibility_trusted() and not ensure_accessibility():
  return
  ```

- 需要调用 AppKit/Quartz（PyObjC）的原生能力（如 route_guard 的 helper 协作、窗口层级）时，**所有原生调用必须 guard 在 `_native_enabled()` 内**——即仅在 darwin 且非 offscreen 时执行。该函数从 `barkit.shell.macos_window` 引入：

  ```python
  from barkit.shell.macos_window import _native_enabled

  if _native_enabled():
  # 仅 darwin 且非 offscreen 时才执行的 PyObjC 调用
  ...
  ```

  offscreen 下（pytest）没有真实 `NSWindow`，PyObjC 调用会崩或无效；这类行为只能真机验证，离屏测试全绿不代表修复。

> 延伸阅读： —— 汇总了项目踩过的 macOS 原生能力非显然坑（如 `-apple-system` 字体告警、`usernoted` kickstart 被 SIP 拦截改 `killall`），写原生调用前先看一眼，避免重蹈覆辙。

## 10. 测试与删除纪律

- **写一条断言 registry 能发现你的组件的测试**。registry 是"目录扫描自动发现"，测试的真正价值是**断言该组件应当被发现**——源码误删或测试误删都会让断言失败、CI 立刻暴露，而不是靠"加载报错"来兜底（见下）。参考 `tests/test_registry.py` 的写法。
- **删除组件必须三处一起删**：① 源码子包目录；② `config.default.yaml` 里的 `plugins.<id>.enabled` 行（及 `hotkeys.<名字>`；业务默认值随 `config_schema()` 一起消失，**没有第二处**）；③ 断言其被发现的测试。
  - 只删配置不删源码 → 因 `enabled` 默认 `True`，组件会**静默自动运行**（残留配置无害，但定制项丢失）。
  - 只删源码不删配置 → 包不在扫描路径里，registry **静默不加载、不报错**，残留配置完全无害。
  - 两种情况都不会"报错"；真正能兜住漏删的是上面那条断言发现的测试。
- offscreen 测试对窗口服务器相关症状（全屏层级、点外部关闭、尺寸传播）**无意义**，不要靠 pytest 全绿声称已修复——真机目测为准。

## 11. 端到端范例：写一个 daemon/execute 型组件

以 `notify_guard` 为参照（完整实现见 `src/barkit/plugins/notify_guard/plugin.py`）。下面给出一个**电量守卫**骨架，覆盖 `start/tick/状态报告/声明/custom 行刷新` 全链路：

> ⚠️ **本例按当前形态写**：声明点方法（`component()` / `state_specs()` / `row_specs()` …）＋ `StateReport`（只报取值名）＋ `StateOption` 取值声明 ＋ `StatusRowSpec.custom` 逃生舱。
> **`BadgeRuleSpec` 已删除**（◷ 2026-09-16，决议 D17）—— 「值得提醒」改由取值声明 `StateOption.alerts`（省略时 `WARN` / `ERR` 为真），见《组件契约规范》§2.5。
> 报告只报取值名、级别与图标归 `StateOption` 声明**已落地**（D12 ＋ D13，2026-09-15）。等价范例另见《组件契约规范》§1.5。

```python
# src/barkit/plugins/battery/plugin.py
from __future__ import annotations

import logging

from barkit.contribution.specs import (
  ComponentSpec,
  IconName,
  StateLevel,
  StateOption,
  StateReport,
  StateSpec,
  StatusRowSpec,
)
from barkit.core.plugin import FAIL_BREAK, RUN_PERIODIC, Plugin

log = logging.getLogger(__name__)

#: 取值闭集（决议 D13）：取值名 / 级别 / 默认文案**只写一次**，报告只报取值名。
#: 列全了框架才画得出颜色与取值图标；列不全就只有「未声明取值」一条路。
STATES: tuple[StateOption, ...] = (
  StateOption("unknown", StateLevel.IDLE, text="尚未读取"),
  StateOption("ok", StateLevel.OK, text="电量正常"),
  StateOption("low", StateLevel.WARN, text="电量低"),
)

def _read_battery_level() -> int:
  """读取电量百分比（示意，返回 0-100）。实际实现可调用 ioreg / PyObjC。"""
  return 100

class Plugin(Plugin):
  id = "battery"
  name = "电量守卫"
  run_mode = RUN_PERIODIC # 框架按 poll 间隔驱动 tick()（须自己写 tick，门禁守一致性）
  failure_policy = FAIL_BREAK # 有"写入/执行"动作 → 连续失败会熔断
  api_version = 3
  order = 50 # 新插件默认插入位（越小越靠前）

  def __init__(self, ctx) -> None:
  super().__init__(ctx)
  self._level = 100
  self._low = False
  self._widgets: dict = {}

  # ---------- 状态报告（运行期唯一真相）：只报取值名 ----------

  def _snapshot(self) -> StateReport:
  # 级别 / 图标 / 默认文案**不在这里**——它们是取值的属性，声明在 STATES 里；
  # 这里只在「这一轮的文案和默认不一样」时用 summary 覆盖默认（决议 D18）。
  if self._low:
  return StateReport("low", summary=f"剩余 {self._level}%")
  return StateReport("ok", summary=f"剩余 {self._level}%")

  # ---------- 生命周期 ----------

  def start(self) -> None:
  # 订阅自己的 status topic（`status_topic()` 与 StateSpec.topic 同源）：
  # 手动广播与 tick 报告都会回到这里刷新 custom 行
  if self.ctx.events is not None:
  self.ctx.events.subscribe(self.status_topic(), self._refresh_ui)

  def stop(self) -> None:
  if self.ctx.events is not None:
  self.ctx.events.unsubscribe(self.status_topic(), self._refresh_ui)

  # ---------- tick（worker 线程）：只计算，返回报告 ----------

  def tick(self) -> StateReport:
  self._level = _read_battery_level()
  self._low = self._level < 20
  return self._snapshot() # 非 None → 框架自动 publish，插件禁自 publish

  # ---------- 手动操作后：同 topic 广播新报告 ----------

  def toggle(self) -> None:
  self._low = not self._low
  self.publish_snapshot() # 基类唯一广播落点：只发自身 topic、只发 StateReport

  # ---------- 声明点方法（框架纯消费；Spec 的 plugin_id 由框架注入，组件一个字不写） ----------

  def component(self) -> ComponentSpec:
  return ComponentSpec(icon=IconName.BATTERY)

  def state_specs(self) -> tuple[StateSpec, ...]:
  return (
  StateSpec(key="main", icon=IconName.BATTERY, states=STATES, # 取值全列举（D13）
  initial="unknown", stale_after=90, # 不给 title：与 Plugin.name 相同就别写
  ),
  )

  def row_specs(self) -> tuple[StatusRowSpec, ...]:
  return (
  StatusRowSpec(
  key="main",
  custom=self._build_panel_row,
  reason="需要行内开关与副文本随报告刷新（逃生舱）",
  ),
  )

  # ---------- custom 工厂（主线程，首次构造后由面板按 identity 复用） ----------

  def _build_panel_row(self, parent=None):
  from barkit.shell.ui_kit import StatusRow, Switch # 工厂内延迟导入

  switch = Switch(parent)
  switch.clicked.connect(lambda _=None: self.toggle()) # 用 clicked 避免回环
  # 图标只给 IconName，**禁 emoji / 禁自拼路径**（同 §12 清单那条）
  row = StatusRow(IconName.BATTERY, "电量守卫", controls=(switch,), parent=parent)
  self._widgets = {"row": row, "switch": switch}
  self._refresh_ui(self._snapshot())
  return row

  def _refresh_ui(self, report: StateReport | None = None) -> None:
  if not self._widgets:
  return
  snap = report or self._snapshot()
  self._widgets["switch"].setChecked(self._low)
  self._widgets["row"].set_sub(snap.summary) # 唯一文案（决议 D18）
```

配套改动（缺一不可）：

1. `plugin.py` 里声明 `config_schema()`（**业务默认值的唯一真源**，别写进 `config.default.yaml`）：
  ```python
  def config_schema(self):
  return FormSchema(plugin_id="battery", fields=(
  FieldSpec("low_threshold", "低电阈值（%）", FieldType.NUMBER, default=20),
  ))
  ```
  加载门控 `plugins.battery.enabled` 由框架管，不归你声明；轮询节律用 `suggested_poll`，**不写 `poll`**（见《配置与热键》§4.1）。
2.（可选）再加一条热键声明：覆写 `hotkeys()` 返回 `HotkeySpec(name="battery_toggle", ...)`；用户可在 `config.yaml` 用 `hotkeys.battery_toggle` 覆盖键位（见《配置与热键》§5）。
3. `tests/` 加一条 `test_registry.py` 风格断言：`battery` 应被发现且 `run_mode == RUN_PERIODIC`。

### action 型对照（autotype）

`action` 组件没有 `tick`/轮询，典型结构是：`ActionSpec`/`HotkeySpec` 触发一个编排方法 → 权限检查 → 业务动作。完整范例见 `src/barkit/plugins/autotype/plugin.py`；最简声明式骨架见 `_template`（`src/barkit/plugins/_template/`，`_` 前缀不加载，复制改名即用）：**动作型从 `plugin.py` 抄、守护型从 `plugin_daemon.py` 抄（复制时改名为 `plugin.py`）**，设置面两种形态都落同目录 `settings.py`（`plugin.py` 里不许 import PySide6，有门禁）。如果你只需要"按一下做一件事"，从 `_template` 或 autotype 抄起，比 daemon 型轻量得多。

## 12. Checklist（发布/合入前自检）

- [ ] `src/barkit/plugins/<id>/__init__.py` 与 `plugin.py` 存在，`plugin.py` 暴露 `class Plugin(Plugin)`
- [ ] `id` 唯一；业务默认值写在 `config_schema()` 里（**不出厂文件**），`config.default.yaml` 里只加 `plugins.<id>.enabled` 这一行加载门控
- [ ] `api_version = 3` 已声明；所声明的 Spec（在各自的声明点方法里）里 key 满足 identity 铁律（**同一声明点内**唯一，不重复写 plugin_id）
- [ ] 读写自己的配置一律走 `self.cfg`（`value` / `set` / `update`），调用点没有第二份默认值（`.get("k", 兜底)`），也没有手写的取值域检查
- [ ] `RUN_PERIODIC` 组件正确设 `failure_policy`（会写系统用 `FAIL_BREAK`、只读刷新用 `FAIL_LOG`），`tick` 跑在 worker 线程、不直接碰 UI、失败 `raise`、返回 `StateReport`（**只报取值名**，级别归 `StateOption` 声明；禁自 publish 状态）
- [ ] 需要权限的组件声明 `required_permissions` 并在使用前引导
- [ ] PyObjC 原生调用 guard 在 `_native_enabled()` 内
- [ ] `custom` 工厂复用 `ui_kit` 元件，圆角随尺寸缩放，主题色取自 `styles.TOKENS`（key 无下划线）
- [ ] `Switch`/`Badge` 用 `clicked` 避免 `setChecked` 回环
- [ ] list 型配置用 `dict` 覆盖模式，不整段拷贝进用户 YAML
- [ ] 写了断言 registry 能发现该组件的测试

## 13. 外部插件：怎么交付与安装

写进 `src/barkit/plugins/` 的是**内置插件**，随 app 一起分发；**外部插件**是用户自己装的，方
式是把它做成一个**独立目录**，里面除插件代码外多一份 `manifest.yaml`（字段表见《组件契约规范》
§「外部插件清单：`manifest.yaml`」）。**包装成 zip 也可以**——用户装的时候两种来源都收。

### 13.1 从零起一个：`barkit new-plugin`

不用先懂契约再动手：这条命令在外部插件根目录下生成 `<id>/`（`manifest.yaml` ＋ `plugin.py`），
重启 BarKit 即被加载。

```bash
barkit new-plugin demo_ext --name "示例外部插件" # 动作型：按需触发 + 设置页 + 操作区按钮
barkit new-plugin demo_poller --daemon # 守护型：常驻轮询 + 自动化开关 + 状态行
```

- 骨架的注释就是上手说明（改哪几处、两条硬约束）；**外部插件只有这一个文件** —— 加载器把
  `plugin.py` 当顶层模块加载，没有包上下文，UI 拆不到 `settings.py`（骨架 docstring 里写了）。
- `--dir` 换落点（默认用户目录下的 `plugins/`；改过 `external_plugins.path` 就用它指过去）；
  目标目录已存在时**直接拒绝**，不覆盖你写了一半的东西。
- 想先看全貌：`example/external-plugin-template/` 是同一形态的手写完整示例，多演示了
  「一个插件能贡献什么」的全集。
- 加载失败不会静默：`barkit doctor` 的「插件发现」组会逐条列出被拒 / 导入失败的插件及原因。

### 13.2 交付与安装规则

安装入口在设置窗「插件」页：**「从目录安装…」／「从压缩包安装…」**。四条要知道的规则：

- **身份与版本以清单为准**：清单里的 `id` / `version` 覆盖类属性上的同名值（与内置插件不同）；
  `version` 缺省读作「未标注」，**不拒载**——版本号不进任何门禁。
- **`api_version` 必须与框架支持的版本精确相等**，不等即拒载；这一条**读清单就能判定**，不
  会 import 你的代码。
- **外部插件不能顶替同 `id` 的内置插件**，会被拒绝（内置插件的 `id` 是保留的）。
- **覆盖已装的同 `id` 插件**时会先给一句「当前 X，用 Y 覆盖？」，点了才落盘；装失败会自动把
  旧版**重新起起来**（不是只把文件换回去）。

压缩包的安全线（不合规的包直接拒收，别指望它「大概能跑」）：不许有越出包根的路径（`../`）、
不许有符号链接、`__MACOSX/` 与 `.DS_Store` 会被忽略；包里**必须恰好有一份 `manifest.yaml`**
（套一层外层目录也认，一层都没有或有多份都拒收）。

> 别把**数据导出包**当插件包 —— 两者文件名长得很像（`barkit-plugin-<id>-<时间>.zip`）。
> 导出包带 `format_version` 标记，安装入口会明确拒绝并提示走「恢复插件数据…」。
