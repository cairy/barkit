# 组件契约 · 决议与证据 · v1

> 这是**台账**，不是契约。
> 契约（「该声明什么」）见 `组件契约规范.md`；本文只记录**每条结论怎么来的、影响哪些文件、什么时候该重开**。
>
> 本文里的 `file:line` 均可在当前工作区复现。**决议落完即过期**，过期条目请移到文末的「已关闭」区。
>
> **口径**：契约规范描述的是**目标形态**。代码与它不一致时，改代码——不因为「现状如此」而降低要求。
>
> **最近一轮**：**D28–D32**（2026-09-14，由《录屏通知设计》触发）——整行点击的落点、托盘底图可配置、「集合型配置」的两问拆分、「前提不满足必须有显式取值」。其中 **D29 的代码已于同日落地**（批次 13 P0，见 D29「落地」行与 §3）。
> **本轮追加 D33**（2026-09-14，由《网络切换设计》§4.5 触发）：**徽标候选列表 → 改现有 `ModeBadgeSpec`，不新增类型**；数据契约已落地，渲染随 P2。
> **再追加 D34**（2026-09-14，用户直接裁定）：**D29 的三处口径被修订**——撤 `StateSpec.as_tray_base`，准入改判「该状态机有没有声明主图标」；`tray.base_source` 改存**状态机身份**（不存事件总线 topic）；回落由「一律回 BarKit 默认底图」改为「有主图标就回落主图标」。**代码已落地。**
> **本轮追加 D35**（2026-09-18，用户直接裁定）：**大窗体（`presentation="window"`）的保存**——新增 `DetailEntrySpec.save`（`FormSaveSpec`：`commit` ＋ `dirty`），**声明了才有「保存」键**；`window` 形态改走原生标题栏（居中、关闭键归系统、去掉「点外部即关」）；关窗时若还脏，在窗内问一句（**不用模态框**，零模态是已定稿红线）。落盘语义随之从「改一格写一次盘」改成「攒在内存、点保存才写」，写盘失败**不回滚**（改掉了旧口径）。**只许配 `window`**，配 `popover` 声明期报错。**代码已落地。**
> **本轮追加 D36**（2026-09-22，由《界面统一》第二批触发）：**组件行普适 ＋ 详情入口两处同源** —— 每个组件**恒有一行**（不声明也由框架合成朴素行），`DetailEntrySpec.trigger` 字段**删除**（声明入口即同时接管整行与底部快捷按钮，两处是同一个过程）。**是行为变更**：`trigger="row"` 的三处组件多出一枚快捷按钮，`recognize` 的整行变可点。**代码已落地。**
> **本轮追加 D37**（2026-09-22，用户裁定）：**显示位默认值逐位不同（快捷区域默认关）＋ 底部栏按实测宽度裁决** —— 出厂 A 区为空，摆哪几个由用户自己勾；摆法是「标签态装得下就用它，否则**整区**转纯图标」，宽度是裁决者、枚数只是意图上界；纯图标态的字形按「动作图标 → 组件身份图标 → 通用齿轮」回落。**是行为变更**：快捷按钮出厂不再出现、没图标的动作不再渲染成文字。**代码已落地。**
