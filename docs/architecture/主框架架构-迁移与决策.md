# 主框架架构 · 迁移计划与决策索引

> 对应主方案 §11–§12 与附录 A/B/C。

## 11. 迁移计划

### 总原则

双轨渐进：v3 骨架先立，旧插件经适配层继续工作，逐个迁移、迁一个验一个。每批次必须可独立回滚。

### 批次 -1 · 安全热修（独立于重构，立即执行）

§7.4.5 P0 的两项是**当前实际存在的本地提权/注入面**，不是重构的衍生问题，单独热修：

| # | 修复 | 文件 | 验收 |
| - | ------------------------------------------------------ | --------------------------------------------------------------------------------- | --------------------------------- |
| 1 | 删 `hev_binary()` 用户域 fallback，缺失即停机 | `plugins/route_guard/helper.py` | 系统域存在时行为不变；手动移走后报「二进制缺失」而非执行用户域文件 |
| 2 | `tunnel.json` 的 `actions` 降级为固定 `wifi` 字段，取消 `type` 分发 | helper + `ipad_tunnel/tunnel_spec.py` + `config.default.yaml` + design.md + tests | 切 Wi-Fi 行为不变；未知/非法项整份拒绝 |

> **必须 bump `HELPER_VERSION`（`2.6.2` → `2.6.3`）**：`daemon.expected_version()` 与 `installed_version()` 都从 helper 源码正则提取版本号比对，源码改了却不 bump，app 会认为「已是最新」→ **新代码永不落盘**。

详细改动方案见 `主框架重构方案-v2-评审意见.md`（历史评审稿，已从 docs 移除，可从 git 历史恢复）或 git 历史（v2.4 版本的 §11 末尾），此处不重复。

> **批次 0 的前置**：基线中 `test_panel_fold_toggles_container_height` 为存量失败项。它属于面板折叠逻辑，而折叠会在 UI 规范落地时被重做（见姊妹文档）。批次 0 不修它，改为在 UI 规范那一轮统一处置——但要在批次 0 的验收记录里显式标注「已知失败 1 项，非本批引入」。

**停止标准**：8 个批次涉及 15k 行代码的大部分，而 §2 非目标明确不做沙箱 / 签名 / 市场，因此必须说清**收益由哪一批次兑现、做到哪一批可以停**。

> **批次 2 完成后必须用「新插件改动文件数 ≤ 2」这个数字重估一次**：若范式样本迁完后，新插件的开发成本**没有实质下降**，说明 Spec 表达力或渲染器设计有问题——应停下来重审 §5，而不是硬推到批次 7。

**批次 2 是分水岭**：notify_guard 是唯一同时具备 daemon + chip + switch + 徽标联动的插件，它迁得顺，后面才有信心；迁得别扭，说明 Spec 设计有问题，应在此处停下来调整。

**批次 4 独立成批**：helper 是 root 常驻进程，改动直接影响系统网络状态，不与其他插件迁移混做。必须一次性完成 label 切换 + 重装，并逐项对比行为（尤其隧道保活与 DNS 复原）。

### 风险登记

| 风险 | 应对 |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 契约层 / Shell 边界划错，Spec 表达力不足 | 批次 2 停下来重审，不硬推 |
| 原语抽象不够，三套 cycle 表达不出来 | 批次 4 停下来重审原语集。**不开自定义能力的口子**——宁可多花一轮设计原语，也不把 root 执行权下放到配置 |
| helper 重装修坏系统网络（断网 / DNS 残留） | 批次 4 前备份 `/etc/hosts` 与路由表；保留旧 helper 副本可回装；改动后逐项验证 |
| **批次 1–3 窗口内卸载 `route_guard` 会连删 hev，打断 `ipad_tunnel`** | 修复随批次 4 对账上线；此前卸载前须确认 `ipad_tunnel` 状态 |
| label 改名 `com.barkit.helper` 后旧 daemon 不会被停 | **必须先加 `LEGACY_PLIST_LABELS` 清理**（bootout 旧 label → 删旧 plist → 再装新 label），并由 `test_daemon_cleans_legacy_label` 覆盖。否则旧 daemon 带着旧代码继续跑，热修间歇性失效 |
| 逃生舱被滥用，退回现状 | §10 自动化检查 + `reason` 强制 |
| 插件卸载有残留 | 批次 6 对每个插件做往返验收 |
| 文件大搬迁导致冲突 | 每批次独立 commit，用 `git mv` 保留历史 |

## 附录 B · 版本矩阵

全文现有 8 个版本号，极易混淆。`HELPER_VERSION` 不 bump 导致新代码永不落盘的教训已经发生过一次，故列表固化。
（第 7 行 `INTENT_VERSION` / `TUNNEL_WIRE_VERSION` 于 2026-09-19 补入：它此前只散在《网络切换设计》与
`doctor D1` 里，而它管的是**跨进程**契约，按本表的分类标准就该在这里。第 8 行 `PROTOCOL_VERSION`
于 2026-09-29 补入：会话线格式的版本，两侧不符即拒绝握手。）

| 版本 | 管什么 | 谁 bump | 不 bump 的后果 | 校验方式 |
| ----------------------- | -------------------------------- | ------------ | ------------------------------- | ----------------------------------------------------------- |
| `HELPER_VERSION` | root helper 的 **core、进程协议与原语集合** | 改 helper 源码者 | app 判定「已是最新」→ **新代码永不落盘**（已发生过） | `daemon.expected_version()` vs `installed_version()`，源码正则提取 |
| `SPEC_VERSION` | **Spec 数据结构**（渲染器读的字段） | 改 Spec 字段者 | 渲染器读到不认识的字段 | Shell 遇更高版本降级渲染并告警，不崩溃 |
| `SUPPORTED_API_VERSION` | **插件契约**（Plugin 基类方法签名） | 改插件基类者 | 旧插件无法加载 | `api_version_reject_reason()`，不兼容则拒绝或由 legacy adapter 适配 |
| `SCHEMA_VERSION` | 用户 `config.yaml` 的顶层结构 | 改配置结构者 | 启动即拒绝（`ConfigError`） | `validate()` 比对 `schema_version` |
| `FormSchema.version` | **单个插件**的配置结构 | 插件作者 | 配置迁移不执行 | 与 `plugins.<id>._schema_version` 比对后跑 `migrations` |
| `INTENT_VERSION` / `TUNNEL_WIRE_VERSION` | app 声明、helper 消费的**意图正文** schema（路由 / 隧道） | 改意图格式者（两侧**同一个提交**） | 真机上旧 helper **整份拒绝**（用户看到「路由不动」）；漏 bump 时连重装提示都没有（2.13.0 实录） | helper 侧**真锁**：意图帧里那版 == 它认的那一版（**含缺位即拒**）；两侧常量相等另有门禁 |
| `PROTOCOL_VERSION` | **会话线格式**（消息类型 / 分帧 / 错误码） | 改 `helper/protocol.py` 者 | 两侧不符 → **握手被拒**（能说清是哪一侧旧，比旧「整份拒」精确） | `protocol.hello()` 自报版本 vs 服务端 `welcome(ok=False, reason=…)` |
| 导出包 `api_version` | 导出包与当前 app 的兼容性 | 导出时写入 | 导入被拒绝 | 导入时校验 |

**判据**：能用 `deep_merge` 兼容的（加字段、改默认值）→ 只 bump 最右两行；涉及跨进程或跨版本加载的 → bump 前四行之一
（线格式那一行**必须与 `HELPER_VERSION` 同批动**：前者是契约门、后者是分布门 —— 只动契约门，真机上的旧 helper 连那把锁都拿不到）。
