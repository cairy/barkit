# 主框架架构 · Shell 渲染层（L3）

> 对应主方案 §6。

## 6. L3 · Shell 层（渲染主权）

### 6.1 核心原则

> **插件描述要什么，框架决定长什么样。**

Shell 独占渲染权：主题、圆角、间距、状态色、图标、字体、hover 态、动画，全部由 Shell 决定。插件提供的数据里不得包含任何视觉属性（无颜色、无尺寸、无字体、无像素值）。

### 6.2 UI 三档约束

| 档位 | 插件写什么 | 框架做什么 | 适用 |
| ---------------------- | ------------------------------------- | ----------------------- | ------------------- |
| **L1 声明式**（默认） | 纯数据 Spec，零 Qt 代码 | 渲染 / 主题 / 圆角 / 间距 / 状态色 | 状态行、芯片、动作、表单类设置页 |
| **L2 CustomPage**（逃生舱） | `QWidget`，但只能用 `ui_kit` 组件 + `TOKENS` | 提供容器、注入主题、托管生命周期与销毁 | 表格 / 树 / 日志流等动态集合视图 |
| **禁止** | 硬编码颜色、自定圆角、emoji 图标、私有字体、改全局 QSS / 自拼内联 QSS | — | 无 |

治理要点：

- 选择权**不在插件**。判定顺序是：Spec 能吃下 → 必须 L1；吃不下 → 才允许 L2。
- `SettingsPageSpec.build` 与 `StatusRowSpec.custom` 必须填 `reason`，否则启动期告警。
- 逃生舱无门槛会导致重构失效——这是本方案最需要守住的纪律。
- **文字排版**（字号 / 字重 / 上色）一律走 `ui_kit.apply_text_role` 的**排版角色**（`caption` / `section` / `chevron`…）：连 L2 页面也不许自拼 QSS，否则同一个「小节标题」会在 6 个设置页里各写一遍（门禁 `test_no_inline_stylesheet`，2026-09-19）。角色表共 **14** 档，**宿主与插件共用**（宿主侧 17 处文字档已收，2026-09-19）；宿主**不进扫描面** —— 它是样式表的实现方，扫它就得开豁免表，违反零白名单，故宿主侧靠评审 ＋ 一条**表自洽用例**（角色里禁颜色字面量、两主题都渲染得出来）守。**哪些进表、哪些不进**的判据写在 `_TEXT_ROLES` 上方：容器档（`background:transparent` / `border-radius` / 下拉与菜单的 QSS）是**布局约束**、自绘控件内部（图标盒烤色 / 按 level 换色的药丸 / 品牌渐变）是**一个控件的完整外观**，两者都不进。
- 禁止项用自动化检查（§10），不靠自觉。

### 6.3 增量更新协议

**问题**：`contributions()` 返回 Spec 列表，若每次刷新都「清空容器 → 按新 Spec 重建」，则 Switch 的焦点、hover 态、进行中的动画全部丢失，行会闪烁，回调闭包反复重建。这是声明式 UI 的 identity 问题。

**解法**：Spec 带稳定 identity，renderer 按 identity 就地更新，不重建。

- `_update()` **只在字段值变化时调用 setter**（`if w.text() != spec.title`），避免无谓重排与信号抖动。
- **回调字段必须重连**：`on_toggle` / `on_click` 是每次 `contributions()` 新建的闭包。就地更新时若 renderer 直接 `connect`，Qt 信号会**重复触发**——一次 toggle 跑 N 次回调。统一策略：**control / 点击类回调一律 `disconnect()` → `connect()`**，或 connect 时显式传 `Qt.ConnectionType.UniqueConnection`。渲染层封装为 `set_callback(widget, signal, fn)`，禁止裸 connect。
- **禁止「清空重建」**。用 `test_renderer_reuses_widget` 守护：连续两次 `sync()` 同一批 Spec 后，widget 实例必须是同一批对象。回调重复触发由 `test_renderer_callback_fires_once` 守护。
- `StatusRowSpec.custom` 改为**工厂函数**而非实例：实例会在每次 `contributions()` 调用时被重建，工厂只在首次构造时调用一次。
> _理由见 「§6.3 增量更新协议」。_
### 6.4 排序规则（三级，唯一真源）

排序是两份文档最容易打架的地方，规则一次定死：

| 层级 | 用什么 | 谁决定 | 作用范围 |
| ------------ | ------------------------------- | ----------------------------------- | --------------------------------------------------------- |
| **插件间** | `plugin_order: list[plugin_id]` | **用户在设置页拖拽**（持久化到 `paths.settings`） | 标题栏图标条、中间状态行、设置窗插件分页 —— 三处**同一个来源** |
| **插件内多贡献** | `Contribution.order` | 插件声明 | 同一插件挂在同一个 point 上的多个贡献之间的相对顺序 |
| **新插件默认插入位** | `Plugin.order` | 插件声明 | 仅在插件首次被发现、尚未进入 `plugin_order` 时使用；一旦进入 `plugin_order` 即失效 |

配套规则：

- `registry.plugin_order()` 是插件间顺序的**唯一调用源**，三处渲染都调它，不允许各自重排。
- 插件卸载时必须从 `plugin_order` 移除 id（§9.1 卸载流程第 3.5 步），否则留孤儿 id 污染排序。
- 框架不做「问题优先浮前」这类动态重排——用户把关键插件拖到前面，三处同步生效，行为可预期。

### 6.5 设计令牌与语义色

```python
# shell/design/levels.py
LEVEL_COLOR: dict[StateLevel, tuple[str, str]] = {
  # level -> (前景色 token, 背景色 token)
  StateLevel.OK: ("green", "green_soft"),
  StateLevel.WARN: ("orange", "orange_soft"),
  StateLevel.ERR: ("red", "red_soft"),
  StateLevel.IDLE: ("text3", "surface3"),
  StateLevel.OFF: ("text3", "surface3"),
}
```

级别由**取值**声明（`StateOption.level`，决议 D13），本文件只是「级别 → 色」的最后一段翻译。

语义色只在此处定义一次，全框架引用。图标统一走 `icons.pixmap(name, size, color)`（要 `QIcon` 就用 `icons.icon(name, size, color)` —— 两个入口签名逐参对齐，**`color` 无默认值**，颜色一律由调用方按当前主题从 `TOKENS` 取），字形自身不感知主题，故跟随明暗；迁移时逐一替换 emoji：`"🧭"` → `IconName.DNS`、`"✨"` → `IconName.GEAR`。

**颜色字面量只许出现在 `shell/design/tokens.py`** —— 2026-09-19 起在 `src/barkit` 内实测**零例外**（AST 扫字符串字面量：41 处全在该文件，`shell/**` 与 `plugins/**` 全零），且由门禁 `test_no_hardcoded_colors` 守着：它的扫描面**同日从 `plugins/**` 扩到全仓** `src/barkit/**`，唯一边界是**定义处那一个文件**（这不是豁免 —— 扫它等于要求令牌表不许定义令牌），`tests/**` 不在面内（那里 21 处字面量正是被测对象：令牌值断言与门禁自证样例）。别再按「宿主是实现方」把面收回去：宿主与插件共用同一套令牌，判据就该同一条。三条不易归类的已就地定案：`red_text` 是**文字**档（`red` 只当填充 / 描边 —— 它当文字浅色下只有 3.55:1）、`on_solid` 是**压在实心色块上的前景**档（主按钮 / 选中态 / 危险按钮 / logo 条形码 / 开关滑块，两套刻意同值，理由见该键注释）、`BRAND_GRADIENT_END` 是**品牌常量**（故意不进 `TOKENS`：品牌色的定义就是不随主题变）。**2026-09-19 起语义色拆四档，每键只有一个角色**（判据与逐格实算 →）：**实体档**（`accent` / `accent_hover` / `red_solid` / `red_solid_hover`）压 `on_solid` 白**字** ≥ 4.5；**图形档**（`green` / `orange` / `red`）压白**图形** ≥ 3.0，两套**刻意同值** —— 它压在菜单栏的角标圆盘上，明暗未知，解出来的答案是同一个；**前景档**（`accent_text` / `accent_text_hover` / `green_text` / `orange_text` / `red_text`）自身就是文字 / 图标 / 描边，压在 `surface*` 或 `*_soft` 上 ≥ 4.5；**浅底档**（`*_soft`）只当底。成因是「**一符两用**」：`accent` 当文字要提亮、当填充就压不住白字，`green`/`orange`/`red` 当图形够、当字崩到 2.0 —— 站点口径（34 个取色位 × 两主题）量出 **33 格**不达标（上一批记的「4 格」是拿记忆当扫描面）。档契约由 `test_semantic_tiers_meet_contrast_contract` ＋ 两条自证守着，**按档的后缀规则推配对**而不是手抄站点清单；另有一条守 `levels.LEVEL_COLOR`（它是第二个「键 → 角色」绑定点，三处消费全是染图形 / 画圆盘压白字形、**没有一处写字**）。品牌标记的渐变起点同日抽成 `BRAND_GRADIENT_START` —— 深色实体档为压白字变深了，品牌图形不该跟着一起闷下去。**待真机双主题目视**（主按钮 / 选中态 / 药丸 / 开关滑块 / 危险按钮悬停 —— 后者顺带把一条无效 QSS `filter: brightness()` 修成了真属性，**是行为变更**）。

### 6.6 徽标聚合（托盘单槽，对齐 D17 / 【契约】§1.4）

```python
# shell/renderers/badge.py —— ◷ 2026-09-19 核对：现名与现形如下（初稿叫 aggregate_tray_badge）
@dataclass(frozen=True)
class Candidate:
  plugin_id: str
  level: str # 代表态级别（**已解析**）
  alerts: bool # 取值作者的提醒意图（StateOption.alerts_on）
  icon: "IconName | None" # 代表态取值图标；None → 画该级别的通用标记
  tooltip: str
  broken: bool = False # 熔断：级别与提醒意图都按 ERR 论，不等失联

def tray_queue(
  candidates: Iterable[Candidate],
  order: Sequence[str], # = registry.plugin_order()（core/registry.py:293）
  *, min_level: str = TRAY_MIN_LEVEL_DEFAULT, # 只认 TRAY_MIN_LEVELS（contribution/specs.py，两档）；ERR 一律露出
) -> tuple[Candidate, ...]:
  """纯函数，无副作用，可单测：算出托盘队列；空元组 = 这一拍不画角标。"""
```

- `reports` 的 key 是 **identity**（不是 plugin_id）——一个插件可有多个 `<key>` 报告，聚合时按 identity 遍历，取最严重级。
- **入参口径（D13 起）**：聚合吃的是**已解析**的级别，不再吃报告——报告只报取值名，级别归取值声明，解析只发生在 `state_view.resolve` 一处（现行签名就是上面那个：`tray_queue(candidates, order, *, min_level)`，入参已是带级别的 `Candidate`）。要用「取值图标」时，由渲染层拿解析结果去查图标，**不得**在聚合里自己回查声明。
- **与 D17 对齐**：托盘是**单槽**，只显示最坏那一级里的组件——角标画该组件的**取值图标**（12 网格字形，取自图标库）并染其级别色；不再用 `NONE/MUTE/ALERT` 三态圆点（那套把「级别」退化成「有无红点」，丢掉了具体取值）。
- `badge_role="mute"/"alert"` 字符串魔法值与 `badge_rules` 参数**删除**：级别由取值自身声明（`StateOption.level`），触发口径统一为「取最坏那一级」，不再另设「触发 alert 的级别」映射。
- 同级并列（多个组件同处最坏级）：渲染层在单槽内按 `plugin_order` **轮播**（见【契约】§1.4 / §2.5），不再接受裸字符串。原 `ui/status_item.py:30` 的 `compute_tray_badge` 与 `app.py:212` 的 `_push_badge` 两处聚合合并为这一个纯函数。

### 6.7 AppShell 装配器

`app.py` 瘦身为启动入口（目标 < 80 行），全部装配逻辑移入 `shell/app_shell.py`：QApplication 设置 → 主题 → Config → EventBus → Scheduler → Registry → 能力注册 → 贡献注册表 → Shell 组件装配 → 退出清理。
