# 主框架架构 · 分层架构与目录结构

> 对应主方案 §3–§4。

## 3. 分层架构

```
L5 插件层 Plugins 只写声明与业务逻辑，不产生 QWidget
L3 界面骨架层 Shell 菜单栏 / 状态面板 / 设置窗，按 spec 统一渲染
L2 能力层 Capabilities 仅「插件自己干不了」的：root 通道 + 权限闸门（极薄）
L1 内核层 Core 配置 schema / 事件 / 调度 / 热键 / 生命周期
L0 平台层 Platform macOS · PySide6 · PyObjC · LaunchDaemon

C 契约层 Contribution 扩展点注册表 + Spec 协议（横切，不参与层号排序）
```

**为什么契约层是 `C` 而不是 `L4`**：L3 要消费 Spec 渲染、L5 要产出 Spec，实际依赖方向是 L3→C 且 L5→C，C 在两者**之下**。若编号为 L4 并画在 L3 之上，就与「上层依赖下层」的规则矛盾。故标记为横切，不参与层号排序。

### 3.1 L2 的收纳标准（本节最重要）

> **框架只提供插件自己干不了的能力，其余一律留在插件内。**

| 能力 | 谁提供 | 理由 |
| ---------------------------- | ------ | ------------------------------- |
| 需要 root 的操作（特权写、路由、DNS、守护进程） | **框架** | 插件无法自己提权，必须复用统一安装的 LaunchDaemon |
| 权限检测与引导 | **框架** | 引导 UI 需全局统一，否则每个插件弹一套 |
| 截屏 / OCR / 条码 | 插件 | 纯用户态，插件自己能干 |
| CGEvent 输入注入 | 插件 | 同上 |
| 通知监听、USB 隧道桥接（用户态部分） | 插件 | 同上 |

反面清单（**框架不再内置**）：`NetworkRoute` / `DnsResolver` / `UsbTunnel` / `ScreenCapture` / `TextInput` / `NotificationObserver`。这些作为框架服务会导致「没装任何插件时也要 import 一堆模块」。改为：需要 root 的部分下沉为 helper 特权原语，不需要 root 的留在插件里。

### 3.2 依赖规则（单向，禁止反向）

- 上层可依赖任意下层
- 下层**禁止** import 上层（含通过字符串、配置、鸭子类型的隐式依赖）
- 同层内 `capabilities` 之间禁止互相依赖
- `plugins/*` 之间禁止互相 import（跨插件协作走 L1 事件总线）
- **C 可被 L1 / L2 / L3 / L5 任意一方依赖**；C 只依赖标准库

**Shell 与契约层的边界**：契约层只定义「有哪些位置、每个位置要什么数据」；Shell 负责「这些数据怎么画」。契约层不得 import PySide6（§10 有门禁），Shell 不得感知具体插件 id。
> _理由见 「§3.2 依赖规则」。_

**三处差**（2026-09-19 核对；「目标」本身不改，只把「还没到」标出来）：

1. **L0 `platform/` 未立** —— 四件都还在原地：`os_permissions` 在 `core/permissions.py`，
  状态栏与窗口两件在 `shell/status_item.py` / `shell/macos_window/`（2026-10-03 由
  `macos_window.py` 拆成包），`launchd` 那半已归
  `capabilities/helper/`（不按本节设想落 `platform/`）。
2. **L2 的形态已改判** —— 实装的不是本节这四件套（「权限闸门 + root 通道」），而是
  **框架提供的可选能力基类**：`capabilities/automation.py::AutomationCapability`（协作式 mixin）
  ＋ `capabilities/helper/`（root 侧）＋ `capabilities/helper_client.py`（app 侧客户端）；
  `Permission` / `PermissionRequired` / `register()` / `require()` / `RootBroker` 均**未实装**。
  裁决与依据见《主框架架构-能力层》§7 开头的 ◷ 块与《插件结构规范-基类与样板》§5.1。
3. **`legacy/` 已删** —— 批次 6 收工时整体删除，`api_version=1` 的兼容通道**已关闭**；
  见《主框架架构-插件可插拔》§9.6。

**迁移原则**：文件移动用 `git mv` 保留历史；每个批次结束必须 `pytest` 全绿。
