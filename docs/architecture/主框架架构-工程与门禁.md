五条特别说明：

- `test_plugin_root_binary_in_closed_set` + `test_root_binary_hash_matches_baseline` 是「物理随插件、授权归框架」的执行者。后者尤其关键：**没有哈希校验，「随插件分发」就退化成「插件自带即可被 root 执行」**，A 类与 B 类再无区别。
- `test_helper_closed_action_set` 与 `test_helper_no_path_param` 是「能力封闭」的执行者——把约束从文档变成 CI 门禁，防止日后有人以「加个例外」的名义重新打开自定义能力。
- `test_capabilities_lazy` 是「框架保持精简」的守护测试（**2026-09-19 入库**：静态扫 `capabilities/**` 的模块级 import，只许标准库与框架自身；另有一条运行期佐证查 `sys.modules`）。
- **关于「视觉等价」的验收**：批次 1/2/3 都写「面板行 / 设置页视觉等价」，但以上全是架构门禁，没有渲染层验证。补 `test_spec_snapshot`：对 `contributions()` 返回的 spec 树做结构化断言，比像素截图稳定得多，能抓住「重构后少了一行 / 顺序变了」这类最常发生的回归。**不引入像素级截图对比作为门禁**——offscreen 环境的字体渲染与真机存在差异，噪声会淹没真实回归。真机目测仍是最终判据，但不应该是唯一判据。
- `test_config_defaults_single_source` 是「配置默认值单一真源」的执行者（**2026-09-20 入库**）：它守的是**文件内容**——`config.default.yaml` 的 `plugins.<id>` 段里除 `enabled` 外多一个业务键就红（5 个内建插件的业务键已全部搬进各自的 `config_schema()`）。两处都写默认值时，改了一处、界面上看不出另一处还钉着旧值：用户读到的默认值与组件实际 fallback 分叉。**反向验证**：把 `resolve_poll: 300` 植入出厂文件 ⇒ 报出 `{'hosts_guard': ['resolve_poll']}`（指到插件 id ＋ 键名）⇒ 逐字节还原 ⇒ 转绿。
> _理由见 「§10 工程规范」。_
