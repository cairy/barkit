# 真机验证清单

BarKit 是 macOS 菜单栏常驻应用。窗口层级、全屏关系、锚点定位、全局热键分别归
**窗口服务器（WindowServer）**与 **CGEventTap** 管 —— 这两处**离屏 pytest 测不出来**。
离屏只覆盖「逻辑与几何」（见 `验证与自证.md`）；**看得见的行为必须真机目测**。

> **本文件放「不随批次变」的部分**：验什么、怎么验、怎么留痕。
> **待验的具体条目**（带日期、背景、预期结论）在 §4。
> 清单是常驻规程，待办是任务状态，**两边别互相抄**。

## 0. 为什么离屏会骗人

离屏（`QT_QPA_PLATFORM=offscreen`）下 Qt 自己当窗口服务器：`setGeometry` 即时生效、层级无意义。
真机上是 Qt 把请求提交给 WindowServer，而它会**合并、延迟、乃至丢弃**某些请求 —— 都是正常行为。
于是同一份代码可以在离屏「全绿」、在真机「没反应」。

| 离屏看起来 | 真机实际 |
| --- | --- |
| `adjustSize()` / `setFixedHeight()` 立刻生效 | 无边框 ＋ 透明 NSWindow 上**缩小请求可能不传播**（放大通常没事） |
| `windowLevel` 只是一个数字 | 与 Space 类型 / 是否全屏组合之后才看得出差异 |
| 热键回调「被调用过」 | CGEventTap 会被系统**超时禁用**，重启走的是另一条独立路径 |
| `QMessageBox` 能 stub 掉 / 离屏永久阻塞 | 置顶窗上真会另开嵌套事件循环，卡死或崩溃 |

## 1. 环境前置（跑之前先记下这六行）

| 项 | 怎么记 | 为什么要记 |
| --- | --- | --- |
| macOS 版本 | 「关于本机」 | 窗口服务器行为随版本变，跨版本的结论不能直接搬 |
| 显示器 | 接了几台、分辨率 | 锚点 clamp / 跨屏定位只在多屏暴露 |
| Space 形态 | 有没有全屏 Space | 「面板浮于全屏之上」只能在全屏 Space 里验 |
| 主题 | light / dark | 令牌回归在单主题下看不出来 |
| 启动方式 | 终端跑 / 打包产物 | 辅助功能授权绑定**启动进程**（TCC）；开发期从终端跑，授权对象是终端本身 |
| 单实例 | 确认没有第二个 BarKit | 第二个进程会打印一行后退出，看起来像「启动失败 / 秒退」 |

启动：`uv run barkit`。日志：`~/Library/Logs/barkit/barkit.log`。

> 升级 Python / 重建 venv 后要**重新绑定权限**（TCC 认的是当时的进程身份）。

## 3. 按场景清单

### 3.1 主面板

- 点状态栏图标 → 面板出现在**图标正下方且居中于图标**（不是屏幕居中）。
- 点面板外任意处 → 关闭；**连续开关 5 次**不出现「打不开」或「位置漂移」。
- 拖到屏幕最右 / 最下 → clamp 生效，不越界。
- 折叠：展开 → 收起，**收起要真的回缩**（历史上反复出问题的一条）。
- 多显示器：把图标所在的那台屏切换主副 → 面板跟到正确屏幕。
- **底部栏（`导读` §5.6 三段式）**：A 区快捷按钮**靠左**、C 区「设置 / 退出」两枚**贴右端**，中间是留白
  —— 若是三块**均分**或按钮撑满整行，说明 A 区末尾的压左留白没生效。C 区**任何数量下都在**、不进溢出。
- 快捷按钮**按实测宽度裁决**（◷ 2026-09-22，D37）：枚数上界与实测总宽**两条都过**才用「图标 ＋ 短标签」，
  否则**整区**转纯图标方块；装不下的折成末端「⋯」。**出厂 A 区是空的** —— 快捷区域默认关（「插件」页那枚芯片是暗的）。
  悬停**纯图标按钮与「⋯」都要出 tooltip**（「⋯」那句要说清藏了哪几个）—— 图标态没有文字，tooltip 是唯一回退。
  失败通常长什么样：一排里**混着「有图标的方块」与「被压扁的文字按钮」**（旧产物）；标签被截成「网络…」也是。
- 点「⋯」→ 浮层**贴着它下方**弹出、**面板不冻结**；点外部或 Esc 关掉且**不误触发**任何动作；
  选中某一项则该动作**当场**跑（面板收起）。失败通常长什么样：「⋯」点了没反应 ／ 面板卡住不动
 （后者是嵌套事件循环，见 §0）。light / dark 各看一遍。
- **C 区只剩设置与退出两枚**：若还看得见第三枚「? 帮助」，说明跑的是旧产物（帮助已于 2026-09-17 删除）。
- **状态区滚动（◷ 2026-09-18）**：把插件装到一屏放不下（或临时把窗口所在屏调成纵向小分辨率）→ 状态区
  应能滚（macOS 上是系统 overlay 滚动条）、滚到底末行**完整可见**；**标题栏与底部栏不跟着滚**；
  折叠 → 展开一轮，看动画期间**不跳变**。放得下的常规情况**不该**出现滚动条（与改前逐像素相同）。
  失败通常长什么样：滚轮没反应（无边框浮层的滚轮转发问题）、滚起来整块面板都在动、常驻一条滚动条。
- **下探到该组件行（◷ 2026-09-18 重启）**：装到状态区放不下 → **折叠**面板 → 点**最后一个**组件的图标：
  展开后它的**首行**应当进了可视区（不是「展开了但你要看的那行还在框外」）。再试两条边界：
  ① 先把面板展开、把列表滚到那行**已经看得全**的位置，收起，再点同一枚图标 → 列表**不该**自己动；
  ② 面板**已展开**时点图标 → 只收起、**不该**滚。手感上留意的也是这两处：多动的位移会让人以为点错了。
- **动作结果反馈条（◷ 2026-09-18）**：让一个**会失败**的行内动作失败 —— 如《网络切换》行内开关写盘失败
 （把配置目录改只读，或用非法场景名）、录屏通知「打开 OpenDisplay」而本机没装 OpenDisplay。
  预期：面板**长出一行反馈条**（失败红 / 成功·部分蓝、成功 5 秒自收、失败留到下一个结果或面板重开），
  **全程不弹模态框**。失败通常长什么样：什么都没发生（结果送丢了）／ 弹了个框（旧产物，或走的是设置页按钮 ——
  那条路本批没接）。
- **整行点击的结果暂时不回访（◷ 2026-09-18，待判「要不要接」）**：点**整行**触发的动作，失败**不进**反馈条
 （行内开关 / 按钮 / 下拉 / 徽标会进）。要判的是「把整行接回去之后，本机那处 `access violation` 还在不在」：
  在 macOS 上把 `HoverRow.mousePressEvent` 的中继临时接回去跑一轮全量，绿则可正式接通。
  依据与取证 →。
- **标题栏图标条**：折叠态点任意一枚 = 展开并**滚到该组件首行**、展开态点 = 收起（与点品牌 logo 同效，
  但 logo 不带下探）；鼠标停在上面应出「组件名：副标题」。
  「识别」与「一键输入」**不该**在图标条里（没有状态机 ⇒ 不声明标题栏，◷ 2026-09-17）——它们的入口是
  组件行、全局热键，以及**用户自己打开**的「快捷区域」按钮（◷ 2026-09-22：该位默认关）。
  若这两枚**图标**还在图标条里，就是在跑旧产物。

### 3.2 设置窗

- 打开设置 → 窗口**浮于面板之上**，别的 app 盖过来之后仍能正常点。
- 逐页切换（含「插件」页）→ 无卡顿、无空白页。
- 「插件」页每行显示位芯片（**最多四枚**：标题栏 / 列表行 / 快捷区域 / 托盘角标）：加上行内开关 / 导出 / 删除之后**是否挤**
 （窗口宽 560，卡片左列是「名称 ＋ 副行 ＋ 芯片」）；亮 / 灭两态在 light / dark 下**一眼可分**。
- 点芯片 → 对应显示位**当场**消失；再点 → **当场**带状态回来。
- 「快捷区域」那枚芯片：**出厂是暗的**（该位默认关，◷ 2026-09-22 D37）；点开 → **底部栏 A 区当场多出该组件的按钮**，
  组件照常运行（它自己的热键仍可用）；再点一下关回默认 → 按钮当场消失。
- **「录屏通知」页的第二枚开关（◷ 2026-09-18）**：设置窗左侧导航点「录屏通知」→ 自动化总闸下面应有一行
  「启动时自动拉起 OpenDisplay」，**缺省是关着的**。打开它 → 退出 BarKit 再启动 → OpenDisplay 被拉起来；
  关着启动 → 什么都不发生；**本来就开着 OpenDisplay 时重启 BarKit → 不该弹它的窗体**（按设计不动它）。
  失败通常长什么样：开关打开但重启没动静（先确认它当时**是不是已经在跑** —— 那是设计如此，不是坏），
  或每次启动都弹一个窗体出来（那是「已在跑也不动它」这条判据没生效）。
  这枚开关在同一页的两行说明文字之间**不该被挤扁**（开关压到点不着就是坏）。
- 卸载确认：问句在 560 宽下**一行放得下**吗；点「卸载」后槽位收起、列表**当场**少一行。
- **模态风险**：设置窗钉在原生层级 `SETTINGS_LEVEL`（201）且带置顶，从它内部弹 `QMessageBox`
  会另开嵌套事件循环 —— 实测症状是**卡住、关不掉、强杀即 abort**（崩溃栈逐帧见
  `tests/test_architecture.py::test_plugin_settings_pages_have_no_modal_dialogs` 的 docstring）。
  两道门禁已各自扫到**整个目录 / 整个 UI 面**：宿主侧 `shell/` 全域（2026-09-17 起）、插件侧按
  AST 判的 UI 面（2026-09-20 起，含 `*_view.py` 运行期窗口）。仍在面外的是 `plugins/autotype/plugin.py`
  那 4 处（域面 ＋ 卡框架反馈通道）与宿主侧 `core/permissions.py` —— 目测时留意「打开某个对话框之后整窗卡住」。

### 3.3 热键

- ⌃⌥O / ⌃⌥P / ⌃⌥M **各触发两次**（第二次验 tap 被禁用后能否自恢复）。
- 与系统 / 其他 app 占用的键位冲突时，给出**可见反馈**，而不是静默失效。
- **辅助功能权限：确实必需**（2026-09-17 实测定论）：关掉系统设置里给**终端**的辅助功能授权、
  **完全退出重开**（BarKit 连同跑它的终端一起退出）后按 ⌃⌥P → 注入**失败**。TCC 撤销对已在运行的
  进程不生效（授权在进程启动时判定），只重启 BarKit、终端还开着会测到老授权而误判「不需要」。
  ⇒ 「维护」页「权限」卡那颗「检查辅助功能权限」按钮 + 引导**不是多余的**，收口落点见 §7。
- **收口后形态（真机目测）**：点「维护」页「权限」卡的「检查辅助功能权限」→ 未授权时弹**行内反馈**（非模态、
  不阻塞）并引导去系统设置；已授权则安静无提示。替代原本从置顶窗 `exec()` 开的模态引导框。

### 3.4 插件生态（装 / 覆盖 / 启停 / 卸载）

- **装**：从「插件」页安装 `example/external-plugin-template/` → 面板出现其行 ＋ 标题栏芯片；
  覆盖提示**落在那条行内反馈槽**上（不是弹框）、与右侧按钮不挤；装完**当场**出现在
  标题栏 / 状态行 / 托盘（考验重扫与重新启用的时效性）。
- **启停**：开关任一外部插件 → 面板行 / header 芯片 / 热键**立即**增删，**无需重启**。
- **卸载**：卸载 → 目录删除 ＋ 配置段清除 ＋ 重启后**不回弹**；内置插件**不可删**（无删除按钮）。
- **卸载「带静态路由的插件」＝ `route_guard`，有延迟收尾**（2026-09-17 起；口径见
  `../architecture/主框架架构-插件可插拔.md` §9.1）：先让某条规则命中的进程跑着、确认路由
  **已加上**（`netstat -rn -f inet | grep 100.64`）→ 点卸载 → 看三点：
  ① 那**一行不是当场消失**（通常 ≤5s 内自己刷掉）——**当场消失反而可疑**；
  ② 路由**真撤净**（同一条命令再跑，命中的都不在了）；
  ③ helper 没在跑时收尾**当场完成**（无消费方＝无需等），且此时路由本就没加过。
  失败分别长什么样：**行留着、也没有红字** ⇒ 判据一直没为真（查 helper 是否在跑）；
  **行没了但路由还在** ⇒ 最坏，延迟没起作用（本项就是为它设的）；
  **槽位出现红字原因** ⇒ 超时放弃，文件 / 配置 / task 声明**全都保留了**，
  这是**可恢复**的（消费方下次自然轮次照样收敛），不是坏账 —— 重试一次卸载即可。
- **拒绝**：把模板的 `api_version` 改到超界 → 被拒且 `barkit.log` 有可读原因，**不崩溃**。

### 3.5 `barkit doctor`（自检，也是留痕工具）

可与 BarKit 同时跑 —— 它不抢单实例锁、不建 QApplication、不提权、不写用户数据。

- A3 的六个依赖应**全过**；C 组应**真跑**并报「内建 N 个 · 外部 M 个」；D / E / F 三组给出真结论。
- 全过时退出码 `0`；有 FAIL 时退出码 `1`、用法错 `2`。
- 有 FAIL 时**照它给的 hint 做一遍** —— 提示有没有真的指到下一步，是「出错信息友好度」的验收抓手。
- `barkit doctor --json` 的输出可直接贴进留痕表或 issue。
- 逐项预期结论见 §4 的 doctor 两条。

> 2026-09-18 实测踩过：2.13.0 那次的版本号**漏 bump**，于是旧守护照旧拒绝、面板只报
> 「规则文件含未知字段」却**没有任何重装提示**（判「过期」靠的就是版本号）。
> 全程拿一块**不承载当前连接**的网卡做，或者先确认自己够得着这台机器。
> 逐项决策理由与判据 →；版本锁 →。

- **网卡三态真读写**（配置窗体 → 场景 → 网络那一块）：跟随系统（`net` 留空 / 只写 `mode: dhcp`）
  ⇒ 命中后网卡**一个字节都不变**（`networksetup -getinfo <服务>` 前后同值，且不留 baseline）；
  固化租约（`pin` 的 ip/mask 留空）⇒ 命中后网卡切 Manual、地址正是**当轮 DHCP 拿到的那个**；
  静态 IP ⇒ 写入配置里的地址。三态切换时那几格该隐藏 / 该置灰的跟着变。
- **「照抄 DHCP」两枚勾选**（固化租约那一态，2026-09-18 新增）：只勾「网关」那一枚 ⇒
  保存后配置里是 `pin: {gateway_from_lease: true}`（**不是**把当时的网关地址抄进去），
  命中后 `networksetup -getinfo <服务>` 的 `Router:` 正是**当轮 DHCP 给的那个**；
  勾上的那一刻同一行的输入框应当场**清空并变灰**，取消勾选又恢复可填。
  切到「静态 IP」再切回来 ⇒ 勾选**不该**自己回来（那是用户取消过的选择），
  静态 IP 那一态的网关框**必须能点**（曾经会因为残留勾选被锁死）。
- **回滚窗口（本项最值钱）**：固化生效后，**在 20 秒内**人为把地址改掉
 （`sudo networksetup -setmanual <服务> <别的地址> <掩码>`）或拔掉网线，看它是否在窗口内
  自动回到 baseline。失败长相：**一直停在坏配置上** ⇒ 探针没生效（大概率是「默认路由不走本网卡」
  那条降级判据把网关比对关掉了，属**有意**，此时只比地址）；**明明配置是好的却回滚了** ⇒
  误回滚，比不报更坏，优先查。
- **`[交还系统]`**：网卡被 BarKit 改过之后，配置窗体页脚与设置页「网络」那块**都应出现**这个按钮
 （没改过时**不显示**，不是灰掉）；按下之后网卡回到进门前那份（**含 DNS**——
  `networksetup -getdnsservers <服务>` 应回到原样，不是只把地址还了）；**连按两次**
  第二次应无任何写动作（幂等：网卡已经停在 baseline 上时不再发命令，否则每轮都会断一次网）。
- **「无匹配时」策略行**（设置页）：默认 `keep`（保持现状）——所有场景都不匹配时网卡**不动**；
  改成 `dhcp` 之后，离开所有场景时网卡应被交还系统。**注意这条是策略、每轮都发**，
  所以幂等性就是它唯一的护栏（同上一条）。
- **非英文系统 / 本地化输出**（预期＝**拒绝改动网卡**，fail-closed）：把系统语言切成德语之类重启，
  看 helper 日志里是否出现「读不出 <服务> 的配置模式（输出可能被本地化），拒绝改动该网卡」，
  且网卡**确实没被碰**。这条是**已知限制**，不是缺陷 —— 要修得先拿到本地化的输出样例。
- **多网卡机器**：两个场景分别配不同网卡时，确认**一次只收敛一张**（第一个命中者胜），
  另一张的 `[交还系统]` 会在没有场景接管它的那一轮轮到（不是丢了，是**顺延**）。
- **停用态**：总闸关掉后按 `[交还系统]` **仍然有效**（动作不是自动化）；而网卡**不会**被自动回滚
  —— 那正是「保持现状」，见 §3.2。

### 3.7 配置窗体（独立窗形态 · 手动保存，◷ 2026-09-18 新增）

打开方式：面板《网络切换》整行。**这一节只验「壳」与保存语义**，表内字段的正确性归 §3.6。

- **居中 ＋ 原生标题栏**：点开应是一个**有系统标题栏的独立窗**（有关闭键与缩放），**居中于触发它的那块屏**
  —— 多显示器下重点核这一条：若居中落在**主屏**而不是图标所在屏，说明取屏取错了。
  失败长相：无边框、没有关闭键（＝ 跑的还是旧的浮层卡形态）。
- **不再「点外部即关」**：窗开着时点面板 / 点桌面 → **窗应留着**。窗开着时点面板其他行 → 换成那一行的详情
 （这是**框架关窗**，不走询问，见下条）。
- **`[保存]` 键**：改一格 → 键出现在窗内页脚；点它 → 给出**行内回执**（「已保存。」）。
  改完**不点保存**直接看配置文件 → 应当是**改动前**的内容（这一条是整批的核心：改与写分开了）。
- **脏时关窗要问**：改了没保存 → 点关闭键 / `Cmd+W` → 窗**不该关**，页脚出一句问话，两个出路：
  「保存并关闭」（存成功才关、失败留在窗内并说原因）／「放弃改动」（关掉且盘上没写）。
  **问句在窗内，不该弹任何模态框**（后者是红线，见 §3.2「模态风险」）。
- **半成品拦在保存前**：删掉某场景的「监控网卡」再去保存 → 应当**拒绝并说清哪一个**，
  且**盘上仍是旧的**（半份场景不许进配置）。
- **两栏分隔**：左右之间拖得动、**拖不到 0 宽**。
- **窗缩到最矮 ≠ 控件被压扁**（◷ 2026-09-18 新增）：把窗往下拖到最短 → 里面的输入框、复选框、
  按钮**高度都不许变**，而应出现**滚动条**（内容保持原尺寸、只是要滚）。失败长相：字被挤掉一半
 （改前实测输入框从 21px 掉到 9px）、或明明屏幕装得下却一开窗就带滚动条（那是初高算错了）。
  顺带看一眼：右栏「路由目标」那个列表**自带**一条滚动条，与整窗的那条并存是正常的（内层是集合
  编辑器），高度够时它不该出现。
- **页脚那两枚仍是即时动作**：`[固定使用]` / `[交还系统]` 点一下**立刻生效**（它们不进保存批次）。

### 3.8 hosts 管理窗（详情卡 · 三页行内编辑，◷ 2026-09-20 新增）

打开方式：面板「hosts 托管」**整行**。**这一节验「零模态 ＋ 统一入口」两件事** —— 改前它是自己
`new` 一枚独立窗（自己管 Dock 显隐），窗里还带 9 处模态弹框。

- **入口归框架**：点整行 → 面板收起 → 管理窗**居中于图标所在的那块屏**、有原生关闭键；
  多显示器下重点核居中落在哪种屏（落在主屏而图标在副屏 ⇒ 取屏取错了）。
- **零模态（本批核心）**：整条流程里**一次都不该出现系统弹框** ——
  - 点「删除」→ 页脚那一行**原地长出确认 / 取消**（不是弹窗）；点取消 → 一条都不该动。
  - 新增 / 编辑里填个坏域名（如 `bad_host`）→ 点保存 → 页脚**红字说清哪里不对**，
  且配置文件**一个字没写**（失败长相：弹了个框，或坏数据已经落盘）。
  - 「新建分类」也是**页内**输入框，不是弹输入框。
- **三页切换不开新窗**：表格 → 表单（新增 / 编辑 / 接管）→ 批量导入，都是**同一扇窗换一屏**；
  页脚「完成」在任何一页都够得着（不该被内容推到看不见的地方）。
- **接管只让选分类**：选中若干**外部**条目点「接管」→ 表单页里「域名 / IP / 更新 / 解析方式 /
  备注」**整组隐去**（那几条各自保留自己的 IP），只剩分类可选。
- **七列表格读得全**：来源 / 域名 / IP / 分类 / 自动更新 / 解析方式 / 状态 —— 每列都不该被截断
 （详情窗初宽 620px 够放；若看到压缩，说明布局被挤了）。
- **管理面只有一个入口**：设置页里**不该**再有「管理条目…」按钮（2026-09-20 删），**也不要**有
  「管理在别处」这类备注（同日删 —— 界面不为已删除的入口留痕）。入口只有面板整行；点开
  之后再点一次、或换到别的组件行再点回来，都应当只有**一扇**管理窗（不该并排出现两扇，
  也不该出现「一扇看不到另一扇刚做的改动」那种两份内容面）。

### 3.9 窗口落位（多屏必看，◷ 2026-09-29 新增）

位置只有 `shell/placement.py` 一处说了算，锚只认「打开它的那一次点击」。验两件事：每档弹窗都落在
**你点的那块屏**的正确位置上；落完之后没被别的东西挪走。

- **每档各来一次、主屏副屏都要**：主面板 / 设置窗 / 详情页浮层卡 / 下拉候选 ⇒ 图标正下方；
  一键输入倒计时卡 ⇒ 屏幕中上（可用高度 30%）；提示浮层与常驻钟 ⇒ 可用区右上角一列；详情页
  窗体态 ⇒ 该屏正中。**失败长相＝跑到屏左上角，或跑到另一块屏**。
- **客观判据（不看眼睛也能判）**：`~/Library/Logs/barkit/barkit.log` 里出现「落位核对」`refixed`
  ⇒ 有别的东西在落位之后动了窗口；出现 `mismatch` 或「认不出窗口该落哪块屏」⇒ 真故障。
  **干净时这三条一条都不该有**；出现就把那一行原样留下。
- **三者共用同一个锚**：面板 / 设置窗 / 详情页都由「你点图标那一下」定位置 ⇒ 相互之间不该错位。
- **多屏两件事**：① 点图标前先看光标停在哪块屏的菜单栏（点另一块屏的图标就该落在另一块屏）；
  ② **早晚各读一次 ＋ 重启后再走一遍** —— 同一份代码下，这枚图标按钮窗口被系统分给哪块屏会变。
- **别拿截图判「窗口在不在屏上」**：没有屏幕录制权限时 `screencapture` 只出壁纸，任何应用的窗口
  都拍不进去 —— 拍不到 ≠ 没显示。
