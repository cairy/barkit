# 文档索引

本文件是 `docs/` 的入口，**只登记开发文档并提供链接，不复述正文内容**。

## 文档导航

- 当前任务 — 进行中的任务进度，接手开发请先读这里
- [架构说明](architecture/README.md) — 分层职责、依赖方向、关键约定、非功能需求、已知技术债
- [组件文档集](architecture/components/README.md) — 组件契约 / 决议 / 插件结构 / 开发指南 / 设计提案
- [操作指南](guides/README.md) — 怎么干：验证与自证（机器能判的）／真机验证清单（只有人能判的）
- 开发日志 — 决策理由与历史封存（只读归档）
- 路线图 — 活路线图（现行事实）
- — 方案工作区（中间态，本索引不逐篇登记）
- `design/` — svg 等设计资源（非文档）

## 文档分类说明

分类标准、状态与流转规则以 `../PROJECT_STRUCTURE.md` 第 7 节为**唯一来源**（自 2026-09-16 起升级为「四类内容 + 一层索引」模型：每篇文档须带 `doc-meta` 元数据，并在本索引的分类登记表登记，由 `scripts/doc_lint.py` 校验）。本索引不重复定义，按需在以下位置查阅：

- 三类分界与维护方式：`../PROJECT_STRUCTURE.md` 第 7.1 节
- 方案流转（草案 → 中间态 → 归档）：`../PROJECT_STRUCTURE.md` 第 7.7 节

## 写作规则

- 单文件 300 行以内，超出就拆分成子目录 + 索引。
- 同一信息只在一处定义，其他地方用相对链接指向，禁止复制复述。
- 新增开发文档必须在上方「文档导航」中登记。
- 日志不登记进本索引，避免索引被历史记录淹没。
- 面向初级工程师：术语首次出现给一句话解释，先结论后原因。
- 任务总结、过程记录、完成报告不生成文件，留在对话或提交信息里。
